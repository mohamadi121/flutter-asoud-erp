# کاربران و دسترسی‌های نقش

## مسیر رابط

منوی عملیات نقش ← کاربران و دسترسی‌ها. کارت بالای صفحه مجوزهای مشترک نقش را باز می‌کند؛ کارت هر شخص و دکمه افزودن کاربر، تخصیص شخصی را باز می‌کنند. افزودن در این صفحه انتخاب یک حساب داخلی موجود است، نه ساخت هویت یا حساب نمونه. فهرست سرور حداکثر ۱۰۰ نتیجه دارد و با جستجو محدود می‌شود.

فرم شامل انتخاب شخص، تنظیم مجوز و مرور/ارسال است. ساده، مشاهده در ماژول را تنظیم می‌کند؛ متوسط جدول‌های بسته‌شونده و پیشرفته همان جدول‌ها به شکل باز است. تغییر حالت هیچ مجوزی اضافه نمی‌کند. ایجاد/ویرایش/حذف نیازمند مشاهده است. مجوزهای موروثی قفل‌اند و ممکن است فقط برای اسناد متعلق به کاربر باشند.

ویرایش اطلاعات با نگه‌داشتن کارت کاربر باز می‌شود. نام، نام خانوادگی، موبایل و وضعیت فعال قابل تغییرند؛ ایمیل شناسه حساب است و در این مسیر تغییر یا جعل نمی‌شود.

## اتصال واقعی

API جدید `asoud_erp.api.v1.user_access` تنها برای System Manager است. از Role، Custom DocPerm، User و Role Profile بومی استفاده می‌کند. مدل فنی `ASOUD Access Assignment` فقط رابطه نقش/کاربر و نقش بومی اختصاصی را نگه می‌دارد؛ مجوزها در JSON یا دیتابیس مستقل اجرا نمی‌شوند.

ذخیره با توکن وضعیت مجوزها و قفل سطرهای مربوط انجام می‌شود؛ ورودی‌ها محدود به DocTypeهای نصب‌شده و چهار عملیات مجازند. اطلاعات قبلی سایر نقش‌ها، مجوزهای شرکت/مالکیت و اشتراک اسناد پاک نمی‌شوند. نقش‌های پایه هنگام تخصیص اعمال می‌شوند و در مرور هشدار مستقل دارند؛ این جدول همه اختیارات آن نقش‌های پایه را نمایندگی نمی‌کند.

نقش‌های اختصاصی در hook استاندارد اعتبارسنجی User، پس از بازسازی Role Profile متصل می‌شوند. نقش غیرفعال یا حساب سیستمی/خود مدیر از طریق این ویرایشگر قابل واگذاری نیست. مجوزهای write/create/delete مربوط به User و System Settings در این ماتریس بسته‌اند؛ مدیریت حساس همچنان در مدیریت بومی انجام می‌شود.

نقش دارای تخصیص شخصی قابل غیرفعال‌سازی نیست. تغییر نقش‌های پایه آن نیز مسدود است تا مجوزهای باقی‌مانده ناخواسته پنهان نشوند؛ تغییرات مشترک ماتریس از صفحه مخصوص نقش انجام می‌شود. حذف تخصیص و مهاجرت نقش‌های پایه، قابلیت این نسخه نیست.

## پیش‌نویس و تأیید

پس از بارگذاری موفق مجوزها، ذخیره پیش‌نویس روی دستگاه مستقل از اعمال سرور است. کلید آن شامل سرور، حساب مدیر، نقش و کاربر مقصد است. بازیابی فقط پس از دریافت مجدد وضعیت سرور و تطبیق توکن ممکن است. پیش‌نویس قدیمی، اعمال آفلاین و بازپخش خودکار مجوزها مجاز نیستند. بازکردن کامل فهرست کاربران در قطع اتصال پیاده نشده است.

موفقیت فقط از پاسخ `applied: true` سرور نشان داده می‌شود. حالت فعال/غیرفعال کاربر با نتیجه اعمال مجوز فرق دارد و مجوز سند نیز همچنان تابع قواعد Frappe است.

## انتشار و بررسی‌های باقی‌مانده

بک‌اند جدید و migrate برای ایجاد مدل فنی باید پیش از استفاده نصب شوند. این کار از داخل این تغییرات روی سرور انجام نشده است.

تست، analyzer، ساخت APK و اجرای عملی سرور انجام نشده‌اند؛ فقط مرور کد و قالب‌بندی Dart انجام شده است. پیش از انتشار عملی باید روی سایت آزمایشی این موارد بررسی شوند: جداسازی دو کاربر، تغییر مشترک نقش، حفظ مجوز پس از ذخیره User، قطع اتصال، تغییر حساب، تداخل هم‌زمان، تأثیر User Permission، مالکیت و عملیات سند، و نمایش در عرض‌های ۳۲۰/۳۹۰/۷۶۸.

مرجع بررسی رفتار بومی: https://github.com/frappe/frappe/blob/version-15/frappe/permissions.py و https://github.com/frappe/frappe/blob/version-15/frappe/core/doctype/user/user.py
