# فرم‌ساز نسخه‌دار آسود

وضعیت ادامه پیاده‌سازی؛ جایگزین گزارش مرحله اول در `form-builder-review.md`.

## مسیرهای رابط

- تنظیمات ← مدیریت فرم‌ها: یک ویرایشگر چهارمرحله‌ای برای درخواست و سند.
- درخواست‌های من ← درخواست جدید ← فرم‌های منتشرشده سازمان: ثبت فرم مجاز.
- تنظیمات ← ثبت سند با فرم: فرم‌های سند با مجوز استاندارد ایجاد سند.
- مسیر فرم‌ها و الگوهای قدیمی حفظ شده و داده‌ها خودکار تبدیل نمی‌شوند.

## قابلیت‌های پیاده‌شده

مشخصات و قالب آغازین؛ بخش‌ها یا تب‌ها؛ افزودن، ویرایش، تکثیر، انتقال و ترتیب فیلد؛ جدول با تنظیم ستون و محدودیت ردیف؛ انواع متنی، عددی، مبلغ، تاریخ شمسی، ساعت، انتخابی، چندانتخابی، بله/خیر، چک‌باکس، اطلاعات سیستم، محاسبه، متن نمایشی، امتیاز و پیوست.

قوانین دارای رابطه و/یا، فعال/غیرفعال، نمایش/الزام/فقط‌خواندنی هستند. چرخه و مرجع حذف‌شده رد می‌شوند. فرمول‌ها عملگر محدود دارند و کد آزاد اجرا نمی‌کنند؛ محاسبه کلاینت پیش‌نمایش و محاسبه مبلغ در سرور ده‌دهی است.

پیش‌نمایش و ثبت از یک رندرکننده استفاده می‌کنند. مجوز نقش/واحد/ترکیب، پیش‌نویس، بررسی مدیر، انتشار، تاریخچه و غیرفعال‌سازی متصل به API هستند. نسخه منتشرشده ثابت می‌ماند و ویرایش بعدی پیش‌نویس است. تغییر نوع ناسازگار، شناسه تازه لازم دارد.

پیش‌نویس طراحی و تکمیل فرم بر اساس حساب، سرور و دفتر روی دستگاه ذخیره می‌شوند. انتشار خودکار آفلاین وجود ندارد. ذخیره مجدد، نسخه پایه را برای تشخیص تعارض ارسال می‌کند. نسخه قدیمی نیمه‌تکمیل خودکار به نسخه تازه منتقل نمی‌شود.

## مرزهای مهم

- امضا، پیوست تصویر است و بارکد/QR ورود کد دارد؛ رسم با قلم یا اسکن دوربین پیاده نشده است.
- قالب‌های آغازین، قواعد تخصصی مانند مانده مرخصی را جایگزین نمی‌کنند. برای آن‌ها اتصال به درخواست/گردش‌کار استاندارد لازم است.
- درخواست مستقل، ثبت داخلی در `ASOUD Form Entry` است. اتصال اختیاری با نگاشت صریح از `workflow_request.create_request` عبور می‌کند. نگاشت پیوست به گردش‌کار در این مسیر رد می‌شود؛ پیوست باید از مسیر استاندارد درخواست ثبت شود.
- آداپتور سند فقط `Journal Entry` و `Material Request` است. از کنترلر استاندارد و مجوز اصلی استفاده می‌شود و تنها پیش‌نویس ایجاد می‌کند؛ `submit()` فراخوانی نمی‌شود.
- رسید سند، ارجاع به سند اصلی نگه می‌دارد، نه دفتر مالی موازی. نمایش آن مقادیر فعلی سند با چیدمان نسخه زمان ثبت است؛ تاریخچه مقادیر متعلق به سند استاندارد است.
- دسترسی طراحی به‌تنهایی مجوز خواندن ثبت دیگران نیست. انتشار فقط برای مدیر سیستم است. سرور شرکت، دسترسی رکورد، مقادیر فقط‌خواندنی، فرمول، فیلتر وابسته و پیوست خصوصی را بررسی می‌کند.

## استقرار

افزونه بک‌اند دارای `api/v1/forms.py`، `services/form_schema.py` و سه مدل جدید `ASOUD Form`، `ASOUD Form Revision` و `ASOUD Form Entry` است. کد استاندارد ERPNext تغییر نکرده است.

پس از پشتیبان‌گیری و استقرار نسخه جدید افزونه، مدیر سرور باید مهاجرت معمول سایت را اجرا کند:

```sh
bench --site <site-name> migrate
```

این فرمان و هیچ عملیات استقرار در این کار اجرا نشده است. فرم‌های قبلی بازنویسی نمی‌شوند؛ تبدیل آن‌ها به قرارداد جدید نیازمند بررسی قواعد اختصاصی و نگاشت است و تبدیل حدسی خودکار اضافه نشده است.

## بررسی

هیچ تستی اجرا نشده است. وابستگی‌ها با فایل قفل موجود آماده، کد Flutter تحلیل ایستا و نحو Python/JSON بررسی شده‌اند. این بررسی‌ها تأیید اجرای واقعی، مهاجرت، ساخت APK یا رفتار روی گوشی نیستند. پیش از بهره‌برداری عملیاتی، بررسی یکپارچگی و امنیت روی سایت آزمایشی لازم است.
