# خانه شخصی آسود

خانه مدیر و کارمند با کامپوننت مشترک `EmployeeHomePage` نمایش داده می‌شود:
سربرگ آسود، پرونده من، تقویم موجود، نیازمند اقدام من و دسترسی سریع.
رنگ‌ها، کارت‌ها، آیکون‌ها و تاریخ شمسی از اجزای موجود پروژه استفاده می‌کنند.
تقویم جدید یا منبع موازی یادآورها در این تغییر ساخته نشده است.

## اتصال‌ها

- پرونده از `PersonnelFileRepository.myHome` و اعلان‌ها از مخزن اعلان فعلی خوانده می‌شوند.
- `HomeInboxSummary` از همان `WorkflowTaskRepository` کارتابل استفاده می‌کند؛
  سه مورد اول در ترتیب سرور، مهلت واقعی و لینک جزئیات اصلی نمایش داده می‌شود.
- گزارش‌ها تابع قابلیت `canSeeAccounting` هستند. عملیات قبلی حذف نشده‌اند:
  داشبورد مدیریتی در «عملیات ← همه عملیات» و خدمات پرسنلی در «عملیات» باقی هستند.
- خطای پرونده یا کارتابل کل خانه را مسدود نمی‌کند. بازگشت از صفحات و کشیدن
  برای تازه‌سازی، اطلاعات خانه را دوباره دریافت می‌کند.

## محدودیت‌های واقعی API

- API کارتابل اولویت ارائه نمی‌کند؛ شمارنده فوری «—» است، نه صفر ساختگی.
  ترتیب مصوب فعلی کارتابل حفظ شده است. برای اولویت‌بندی واقعی باید قرارداد
  اولویت و ترتیب در سرور و کارتابل با هم توسعه یابد.
- سقف دریافت فعلی کارتابل ۲۰۰ است؛ در این حالت شمارنده «۲۰۰+» و توضیح محدودیت
  نمایش داده می‌شود. شمارنده معوق بر اساس موارد دریافت‌شده است.
- پرونده فعلی یک سمت/واحد ارائه می‌کند؛ تغییر «سمت فعال» نیازمند قرارداد نشست
  و مجوز سرور است و کنترل نمایشی بدون پشتوانه اضافه نشده است.
- کاربر فاقد پرونده پرسنلی، وضعیت خطای همان بخش را می‌بیند؛ هویت ساختگی
  جایگزین داده واقعی نمی‌شود. داده نمایشی فقط در حالت پیش‌نمایش برچسب دارد.

تست اجرایی بنا به درخواست کاربر اجرا نشده است؛ تغییر انتظارهای تست‌ها به معنی
تأیید اجرای آن‌ها یا تأیید ساخت APK نیست.
