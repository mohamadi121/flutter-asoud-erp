# اقدام خودکار، نسخهٔ ۲

صفحهٔ جدید `AutomaticActionPage` برای مرحله‌های تازه یا تنظیمات `schema_version: 2`
باز می‌شود. تنظیمات قدیمی در `StageSettingsPage` حفظ شده‌اند؛ ورود به فرم جدید
تأیید می‌خواهد و تا ذخیره، تنظیمات قبلی تغییر نمی‌کنند.

- هفت نوع عملیات با مدل‌های مستقل `AutomaticOperation`؛ فقط فیلدهای نوع انتخابی ارسال می‌شوند.
- نگاشت هر فیلد در پنل پایین: موجودیت فعلی، خروجی مرحلهٔ مشخص، مقدار ثابت یا سیستم.
- مقدار ثابت تاریخ با `AsoudFormDateField` شمسی نمایش داده و ISO ارسال می‌شود.
- اعلان داخلی و ایمیل؛ گیرندگان صریح و درخواست‌کننده؛ متن سفارشی یا پیشنهادی.
- مسیر موفقیت با شناسهٔ مرحلهٔ واقعی؛ خطا فقط توقف یا وظیفهٔ کاربر.
- تعداد تلاش اضافه، فاصلهٔ افزایشی و مهلت فنی؛ ممیزی غیرقابل خاموش‌کردن.
- ذخیرهٔ تنظیمات و مسیرها از یک API اتمیک؛ خطای سرور به موفقیت محلی تبدیل نمی‌شود.

فرم، متادیتا را از `asoud_erp.api.v1.automatic_actions.options` می‌خواند و با
`automatic_actions.save` ذخیره می‌کند. متادیتای معتبر آخرین بار برای همان حساب،
سرور و مرحله روی دستگاه نگهداری می‌شود و فقط هنگام خطای شبکه/سرور قابل استفاده
است؛ با این حال سرور هنگام ذخیره، مجوز و اعتبار تنظیمات را دوباره بررسی می‌کند.
ذخیرهٔ آفلاین از صف mutation موجود استفاده می‌کند و هنگام بازشدن دوبارهٔ فرم،
آخرین تغییر صف‌شده برای همان حساب بازیابی می‌شود. اطلاعات ساختگی استفاده نمی‌شود.
نبودِ کاربر سیستمی محدود با هشدار مشخص است و اجرا متوقف می‌ماند.
انتخاب انتقال وضعیت به پیکربندی هویت سیستمی و گردش‌کار استاندارد وابسته است.

دامنهٔ اولیهٔ سندها: Material Request و Journal Entry؛ رکورد درخواست ASOUD نیز
پشتیبانی می‌شود. جزئیات اجرای واقعی، مهاجرت DocType، محدودیت رابطهٔ مبتنی بر
Comment و راه‌اندازی حساب سیستمی در `docs/automatic-actions-v2.md` مخزن بک‌اند است.

درخواست `automatic_actions.options` باید به‌عنوان خواندنی مستقیماً به سرور برود؛
قرار دادن آن در صف mutation باعث ردشدن آن در اعتبارسنجی همگام‌سازی می‌شود.
وجود endpoint در کد مخزن بک‌اند به‌تنهایی نصب آن روی سرور عملیاتی را اثبات نمی‌کند.
